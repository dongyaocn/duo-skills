# 架构债务台账（duo-debt）

登记、分级、追踪架构/技术债，并给出与工单排期联动的偿还建议。核心洞见：**duo 工单 Comments 的【不修留档】是债务的天然进项**——每轮验收沉淀的留档项自动入账，债务台账不再是摆设。

## 输入

- 无参：输出当前台账总览
- `登记 <描述>`：手动登记一条（交互补全分级字段）
- `收割`：扫描全部工单 Comments 的【不修留档】项，比对新账（按描述相似+来源工单去重）入账
- `偿还建议`：结合当前工单排期给窗口建议

## 台账结构（`docs/tech-debt.md`，不存在则建）

```markdown
# 架构债务台账

| ID | 描述 | 来源 | 发现日期 | 利息 | 触碰频率 | 修复成本 | 状态 | 备注 |
|----|------|------|----------|------|----------|----------|------|------|
```

- **来源**：`工单NN留档` / `验收发现` / `手动登记`；
- **利息** = 触碰频率 × 修复成本（高息=常改区域的重构债；低息=孤立遗留）：
  - 触碰频率：高（几乎每个 feature 都碰）/ 中 / 低（孤立模块）；
  - 修复成本：小（≤1 天）/ 中（数天）/ 大（需独立排期）；
  - **高息小成本** = 最优先偿还（性价比之王）；高息大成本 = 架构师专项立项（走 /duo-adr + /duo-intake）；低息一律排后；
- **状态**：`在账 / 已排期(工单NN) / 已偿还(工单NN) / 已失效`。

## 偿还建议（与排期联动）

1. 读当前 feature 的工单状态与 `/duo-reschedule` 的并行组（有则用）；
2. 规则：
   - **高息小成本**债 → 建议插当前 feature 的并行波次空档（独立小票形态，参照"安全补齐类插空"模式）；
   - **高息大成本**债 → 建议单独立项（给出它自己的 spec 种子：痛点=台账描述，走 /duo-intake）；
   - 触碰频率"高"且**与新 feature 范围重叠**的债 → 建议"顺手偿还"：在拆单时并入相关票范围（由 /duo-intake 消费本台账）；
3. 输出建议表（`| 债 | 级别 | 建议 | 依据 |`），不自动开工单——确认后由用户指定走 /duo-intake 或直接 /duo-dispatch。

## 边界

- 收割只认【不修留档】显式标记，不猜测隐性债务；
- 台账是文档不是数据库——单表 markdown，行数 > 100 时提示归档已偿还项到文末"历史"节；
- 已被后续工单顺带修复的留档项，收割时检测代码现状后标"已失效"（对照来源工单的文件锚点 grep）。
