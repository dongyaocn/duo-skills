# 交付驾驶舱（duo-portfolio）

给技术总监/项目经理的**全局视图**：跨 feature 工单健康度、交付效能度量、风险预警。只读分析，不动任何工单。

## 输入

- `<范围>`（可选）：`.scratch/` 下全部 feature（缺省）或指定 feature 列表
- `html`（可选）：追加输出 HTML 驾驶舱（商务蓝风格，落 `temp/portfolio-<日期>.html` 并打开）

## 数据源

`.scratch/*/issues/*.md` 全量（Status 行 + Comments 轮次/时间戳/留档/移交）+ `.scratch/*/reports/*-review*.html`（验收数据）+ 各仓 git log（--since 默认近 14 天，可覆盖）。

## 三视图（控制台 markdown 输出）

### 视图一 · 进度

```text
| Feature | 工单 | ✅完成 | 🔄在飞 | 📥待办 | ⛔人工 | 完成度 | 最后活动 |
```

- 完成度 = done / 总数；"最后活动"取该 feature 最近一次工单状态变更或提交时间；
- 停滞预警：最后活动 > 3 天且存在非 done 票 → 标 `⚠ 停滞`。

### 视图二 · 效能（度量口径全部来自真实工单文本）

| 指标 | 口径 |
|---|---|
| 一次通过率 | round 1 即 ACCEPT 的票 / 总 ACCEPT 票 |
| 平均轮次 | Σround / ACCEPT 票数 |
| 打回原因分布 | REJECT 小节按【硬违规/未申报扩展/顺带修/不修留档】归类计数，硬违规再按主题聚（如"脚本自伤 N 次/环境陷阱 N 次/业务缺陷 N 次"） |
| 代修率 | Comments 含"验收代修"的票 / 总票 |
| 周期时间 | 每票 claimed 时间 → done 时间的均值（中断票标注剔除口径） |
| 并行利用率 | 有 `并行组` 标注的票 / 总票 |

打回原因分布是流程改进的直接输入：脚本自伤多 → 回灌简报规范；环境陷阱多 → 回灌陷阱库（衔接 duo-review 第 10 步）。

### 视图三 · 风险雷达

扫全部未 done 工单与 Comments，列出：

- `ready-for-human`（Rejects 满 2 升级待裁决）——最高优先；
- `needs-info` 停滞 > 2 天；
- 依赖断链：Blocked by 指向的票不存在/编号错；
- 留档未消：全部【不修留档】项汇总（来源工单+一句话），按是否已有移交去向分类；
- 移交未闭环：Comments 含"移交 <NN>"但目标票无对应范围记载。

## 边界

- 度量只统计能从文本确证的数字，缺时间戳的票该指标记 `—` 并注明剔除数；
- 不做个人绩效对比（度量对象是流程与工单，不是人）；
- HTML 驾驶舱数据必须与控制台输出一致（同一数据源渲染）。
