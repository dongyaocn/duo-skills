# UI 视觉设计（duo-ui）

三种模式：**设计**（产出/迭代高保真稿）、**评审**（实现截图 vs 设计稿差异标注）、**规范**（设计 token 提炼维护）。核心方法论：**HTML 高保真稿即视觉与契约基准**——比静态图强在可交互预览、可复制样式源头、可逐屏拍板留痕。

## 输入

- `设计 <需求/屏描述>`：新屏或改屏（可给文案/草图/参考截图）
- `评审 <设计稿屏> <实现截图路径>`：差异标注
- `规范`：提炼/更新设计 token

## 设计模式

1. **读上下文**：需求要点 + 既有 `design/ui-mockups.html`（存在则**续编号同风格迭代**，不另起炉灶——同文件追加新屏保持 token 一致）+ 项目组件范式（uniapp+uView 移动端 390 视口 / FastAdmin 桌面范式 admin 端，按项目实际探测）；
2. **产 HTML 高保真屏**（追加进 ui-mockups 或新建，单文件无外链、深浅色自适应）：
   - 每屏至少覆盖**关键态**：默认 / 空态 / 错误或驳回 / 加载（按屏语义裁剪，注明）；
   - 屏内可交互（tab 切换、弹层开关用纯 CSS/JS 切换）；
   - 屏编号 + 标题 + 状态徽章（`待确认` / `已决 r<N>`）；
   - 移动端一屏一卡片纵排；admin 端桌面布局；
3. **确认清单**（两轮拍板机制）：输出逐屏确认表——每屏一行：`| 屏 | 要点 | 状态（待确认/修改后待确认/已决）|`；用户逐屏拍板（通过/修改意见），修改后重出该屏直至"已决"；**两轮未决自动升级**列分歧点请用户裁决；
4. **已决屏入册**：全部已决后，ui-mockups 头部"已决清单"节登记（屏号+拍板日期），此稿即后续工单的**视觉基准**；
5. 提示衔接：`/duo-intake` 拆单时引用（工单验收节写"视觉：对照 ui-mockups <屏号>"，shot-* 脚本按屏断言）。

## 评审模式

1. 读设计稿目标屏（提取布局结构与文案基线）+ 实现截图（temp/ 路径）；
2. 逐区差异表：

```text
| 区 | 设计稿 | 实现 | 差异 | 严重度 |
| 信息卡 | 三态徽章 | 仅两态 | 缺"驳回"态 | 阻断（态缺失） |
| 按钮 | 主蓝#1e4fd8 | 偏浅 | 色值偏差 | 细节 |
```

3. 严重度两级：**阻断**（态缺失/交互缺失/文案错误）、**细节**（间距/色偏/字号）；阻断项必须修，细节项列给用户裁量；
3. 复修后重截图复评至阻断清零。

## 规范模式

1. 从已决设计稿 CSS + 项目实现样式（uView 主题变量/全局样式文件）提炼 **token 表** → `design/tokens.md`：

```markdown
| 类 | token | 值 | 用途 |
| 色 | primary | #1e4fd8 | 主操作/强调 |
| 字号 | title-lg | 22px | 页标题 |
| 间距 | card-pad | 16px | 卡片内边距 |
| 组件 | 状态徽章 | 胶囊 12px/600 | 待审/通过/驳回 |
```

2. 已有 tokens.md 时做**双向对账**：设计稿新用而未登记的 token 补录；实现里偏离 token 的列差异表；
3. token 表供设计模式复用（新屏只准用表内值，新值先入表）。

## 边界

- 设计稿是基准不是实现——不写业务代码，产出仅 ui-mockups/tokens 文档；
- 文案以需求方提供为准，设计稿自拟文案标 `（示意）`待确认；
- 无既有设计体系的项目：首次设计模式先产 3-5 屏核心流 + 规范模式建 token，再扩展；
- 评审模式的截图来源由调用方提供（验收流走 shot-* 脚本产物）。
