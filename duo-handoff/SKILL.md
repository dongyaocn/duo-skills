# 会话交接（duo-handoff）

在会话终止前把 duo 流水线的当前局面固化成一份交接文档，让**没有本会话上下文的新 agent** 无损续跑。与相邻 skill 的分工：

- **duo-status**：看板查询（用户主动查，只读控制台）
- **duo-summary**：即时复盘（关键节点后主动输出，控制台不落文件）
- **duo-report**：正式归档日报（HTML 文件，入 reports/）
- **duo-handoff**：**会话态固化**（终止前一次性，落项目 `.scratch/handoffs/` 可追索，面向下一个 session）
- **memory**：跨会话的持久事实（用户偏好/项目约束）；handoff 管**本次会话的临时局面**——工单进度快照、运行态时点、待办清单。两者互补：durable 走 memory，session 态走 handoff。

## 触发时机

1. 用户明示要重启 session / 清上下文（compact 后上下文质量下降时也宜主动建议）
2. 换机器/换环境续跑前
3. 长流水线中断点（用户离开前主动提议，回来即有续跑锚点）

## 输入

- `<下个 session 聚焦方向>`（可选）：用户给的交接后重心，写进文档开头定向下一 session

## 流程（顺序执行）

### 1. 交接前收尾——交接的是干净现场

写文档前先做三件收尾（有授权的运行态自管范围内自主做，超范围先请示）：

1. **运行态**：盘点本会话拉起的后台任务/dev server/探针进程——该停的 TaskStop（并在文档记下重启方法），需常驻的标注归属与探活方式
2. **临时造态**：演练造的测试数据/会话/账号已清则确认，未清的列清单交下一 session（勿默默留下漂移源）
3. **git 现场快照**：双仓（或多仓）各自 `git status --short` + `git log --oneline -3`，未提交资产逐项列进文档待办——**这是下一 session 的第一件事素材**

异常产物（事故性文件、命名古怪的未知文件）：查明形态（`file`/大小/mtime）后写入文档，标注处置建议与授权要求（删除类操作需用户确认），内含敏感值（cookie/凭据）的明示"勿外传"。

### 2. 写交接文档

落点：**本项目 `.scratch/handoffs/YYYY-MM-DD-<slug>.md`**，随主仓库 git 管理可追索——临时目录（/tmp、%TEMP%）会被系统定期清理，历史交接将无法追索（2026-11-26 用户定则）。历史交接按日期堆叠成会话史；写新交接前先看上一份，把其待办逐项核对（已清/未清）带入新文档。项目不可写或用户明示不入库时才降级 OS 临时目录，并在文档头标注降级原因与时效。

六节结构（全部中文）：

```markdown
# 交接文档 · <项目> · <YYYY-MM-DD HH:mm>
> 一句话：交接缘起与下一 session 起步姿态

## 一、主线状态
| Feature | 状态 | 凭据路径 |
（路径引用为主——spec/issues/提交号，**不复制其内容**）

## 二、环境与运行态（交接时点）
- docker/dev server/本地 .env 本地态标记（哪些仅本地、生产零影响）
- 已停掉的运行态 + 重启方法（指向 memory 或文档路径）

## 三、下一 session 待办（按优先级）
- git 收尾提交 / 异常产物处置（标注需授权）/ 可选项与留档项

## 四、分支与安全约束（沿用）
- 当前分支/主分支/已合入记录
- 本项目行为铁律与安全红线（引用 CLAUDE.md/memory，只摘下一 session 开工即需的）

## 五、suggested skills
- 下一 session 按需调用 Skill 工具的清单（开场看板/汇报/派工验收等，各带一句话何时用）

## 六、memory 索引
- 本项目 memory 条目名列表（供交叉引用，内容不复制）
```

### 3. 硬规则

- **路径引用不复制**：spec/issue/ADR/commit 已固化的内容一律引用，不抄进文档（防双源漂移）
- **脱敏（红线级——入库即 git 历史永久留痕，无法撤回）**：凭据/密码/token/cookie 值/PII 不入文档；需要指向时引用单一事实源路径
- **授权标注**：待办里涉及删除/回滚/外发的事项，明示"需用户授权确认"
- **事实核验**：写入的 git 状态/版本号以当轮命令输出为准，不凭记忆

### 4. 交接确认

向用户输出简短收尾：文档路径与提交号、交接前做了哪些收尾、下一 session 起手建议（通常：`/duo-status` 看板确认 → 待办第 1 项 → 待命）。

## 边界

- 只固化与续跑相关的状态；流水线本身的推进（派工/验收）不在交接时新开
- 不做 git 提交/推送（未提交资产是交给下一 session 的待办，不是本 skill 的收尾动作——除非用户明示）
- 交接文档是会话史的一部分而非工单资产：落 `.scratch/handoffs/` 入 git 供追索，但不替代 spec/issue/memory 的职责——确需持久化的结论仍归位到正轨
- 空闲期交接（无在飞任务）也照常产出，待办节可只有例行善后——文档本身就是"此刻无事"的证明
