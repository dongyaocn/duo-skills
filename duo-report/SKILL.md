# 工作日报生成（duo-report）

按日期范围把 duo 工单流转与 git 提交汇编成一份 HTML 日报，五套风格任选。输出为**单文件 HTML**（无外部依赖、深浅色按所选风格定）。

## 输入

- `<日期范围>`（可选，缺省=今天）：`2026-11-20`、`2026-11-18~2026-11-20`、`yesterday`、`this-week`
- `<风格 1-5>`（可选，缺省=3）：见下文五套风格规格
- `<feature>`（可选）：限定单个 feature；缺省=全部

## 数据源（与 duo-status 同源 + git）

1. `.scratch/<feature>/issues/*.md` 四态解析（规则同 duo-status）；
2. `.scratch/<feature>/reports/NN-review*.html`：提取各套件测试计数、四步验收结论、代修记录；
3. `git log --since=<起> --until=<止 23:59:59> --pretty=format:'%h %ad %s' --date=format:'%H:%M'`（主仓库；双仓票另加实施仓库，路径从工单登记或 AGENTS.md 推导，不可达则跳过并注明）；
4. 验收报告 images/ 截图（可选入报，默认不嵌）。

**真实性铁律**：所有数字必须来自上述真实来源（工单文本/HTML 报告/git log），禁止编造或推算"估计值"；数据缺失处写 `—`。

## 日报结构（大厂标准，全部风格共用）

1. **报头**：`工作日报` + 姓名（git user.name）+ 日期范围 + 生成时间；
2. **今日概览（KPI 行）**：完成工单 N ｜ 进行中 N ｜ 待办 N ｜ 提交 N 次 ｜ 断言通过 N/N ｜ 打回 M 次；
3. **完成事项**：每张 done 工单一条——标题、一句话成果（从工单目标行提炼）、验收数据（测试计数）、合并提交、轮次；
4. **进行中**：claimed 工单 + 当前进度一句话（从报告/日志尾部判断，判断不了写"实施中"）；
5. **明日计划**：从 ready-for-agent 工单与工单依赖行推断（注明"按当前依赖排序"）；无待办时如实写"无排期事项"；
6. **关键风险与依赖**：ready-for-human（人工裁决）、Rejects 满 2 的、跨工单移交事项（工单 Comments 中"移交"字样）；
7. **提交时间线**：git log 逐条（时间/短号/信息），双仓分列；
8. **打回与返工记录**（期间有 REJECT 时）：每轮一句摘要 + 修复结论。

## 五套风格规格

**风格 1 · 极简白（Notion 风）**
- 白底（#fff）近黑墨色（#37352f）、正文 15px/1.7、大量留白、1px #e9e9e7 细分隔线全宽；
- 无卡片无阴影；KPI 行是纯文字 + 粗体数字；标题用 600 字重不加色；
- 状态用文字前缀（✅/🔄/📥）不用色块；整体像一页排版干净的文档。

**风格 2 · 科技深色（GitHub Dark / Linear 风）**
- 深底 #0d1117、面板 #161b22、边框 #30363d、正文 #e6edf3、次要 #8b949e；
- 强调色 #58a6ff（链接/数字）、成功 #3fb950、警示 #d29922；数字/提交号用等宽字体（ui-monospace）；
- KPI 做成一行五个"终端面板"格子（1px 边框无圆角或 6px 小圆角）；表格斑马纹 #0d1117/#11161d。

**风格 3 · 商务蓝（飞书/钉钉企业风）——默认**
- 白底、页头深蓝通栏（#1e4fd8→#3b82f6 渐变）白字标题区；正文卡片白底 12px 圆角 1px #e5e7eb 边 + 极浅投影；
- KPI 四宫格卡片（图标 emoji + 大数字 + 灰标题）；状态徽章胶囊（绿 #10b981/蓝 #3b82f6/橙 #f59e0b/灰）；
- 章节标题左侧 4px 蓝竖条；表格头浅蓝底 #f0f5ff。

**风格 4 · 数据驾驶舱（Grafana 风）**
- 深灰蓝底 #111827、卡片 #1f2937、网格布局（KPI 一行 6 卡 + 主区两栏）；
- 每个数字超大（28-34px 等宽）配微型趋势条（用 CSS div 宽度百分比模拟，数据=每日提交数）；
- 强调色青 #22d3ee 与紫 #a78bfa 双色系；断言通过率画成水平进度条（绿>90%/黄>70%/红）；卡片标题全大写 11px 字距加宽。

**风格 5 · 杂志风（Vercel/Stripe 营销页风）**
- 白底、报头超大标题（40px 无衬线粗体）+ 日期范围用衬线斜体（Georgia）；
- KPI 行是"大数字 + 下划短线"排版（数字 32px、下方 40px 宽 3px 黑色短横）；
- 章节用"01/02/03"序号 + 大写小字母间距标签；分隔用 1px 黑线；
- 单一强调色自选（建议 #0070f3）；表格极简无线框仅行线；页脚居中小字。

五套共性：`<meta viewport>` 自适应、中文字体栈（-apple-system,"PingFang SC","Microsoft YaHei"）、单文件无外链、打印友好（@media print 隐藏交互元素）。

## 输出与落盘

- 路径：`temp/report-daily-<起>[_<止>]-s<风格号>.html`（temp/ 为项目临时产物约定目录）；生成后用系统默认浏览器打开（Windows：`start`；WSL 侧生成则经 /mnt 路径调用 Windows 打开）。
- **不入 git**（展示性产物；用户明确要求存档时再拷贝到指定位置）。
- 控制台同步输出一行摘要：`日报已生成：路径 ｜ 完成 N · 进行中 N · 提交 N ｜ 风格 S<号>`。

## 边界

- 日期范围内无任何工单与提交：仍生成报告，完成区写"本期间无完成事项"，不虚构。
- 双仓/多仓提交去重：同一工单在主仓库的归档提交与实施仓库的功能提交分别列出，标注仓库名。
- 用户要求"5 套全出"时循环生成五个文件并逐一打开。
